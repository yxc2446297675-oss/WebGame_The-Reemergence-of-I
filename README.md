# 《潜伏危机：循环伪装体》 (Project: Doppelganger)

> **技术栈**：HTML5 / CSS3 (Grid & Flexbox) / 原生 JavaScript (ES6+ 模块化) / Canvas 2D 绘图引擎  
> **核心类型**：文字冒险 (AVG/VN) × 肉鸽迷宫探索 (Roguelike) × 阵营身份推理 (Social Deduction)  
> **设计特点**：纯前端零依赖、轻量单页架构、沙箱安全存储降级、全平台/移动端/Iframe响应式自适应。

---

## 📌 项目亮点与设计初衷 (面试精要)

本项目旨在以纯原生 Web 前端技术，构建一套具备**高度可扩展性、严谨状态流转与数据驱动机制**的互动叙事推理游戏。
不同于传统的线性视觉小说或单一纯规则桌游，本项目创新性地将**图论分支迷宫探索（肉鸽）**与**不完全信息博弈的伪人身份推理**深度结合：
1. **有限状态机 (FSM) 驱动核心循环**：基于严格的 `q1 -> q2 -> q3 -> q4 -> q5 -> q6 -> q7` 昼夜交替推进模型，确保游戏逻辑的确定性与强壮性。
2. **动态图论与战争迷雾 (Fog of War)**：基于邻接表与距离扩散算法实现的迷雾系统，通过 Canvas 进行动态可视化渲染与路径寻址。
3. **数据驱动与高延展架构**：关卡拓扑、身份阵营、动态伪人生成区间、NPC 行为台词树均与核心逻辑完全解耦，支持无需重构代码的任意拓展。
4. **沙箱安全与跨端适配**：深度适配各种 Web 运行环境（本地 `file://` 双击离线运行、Webview、Iframe 嵌入及平台部署），内置 LocalStorage 安全探针与内存自动降级方案。

## 🕹️ 核心游戏机制与数学模型

```
[q1 开局黑屏沉浸] ➔ [q2 遗迹苏醒] ➔ [q3 肉鸽探索移动 (消耗体力8/步, 遇食物/NPC)]
                                          ⬇ (步数检定触发傍晚)
[q7 白天公布 (暗夜结算/伤亡)] ⬅ [q6 暗夜行动] ⬅ [q5 裁决协议 (禁锢/放逐)] ⬅ [q4 傍晚深度询问]
```

### 1. 动态伪人生成区间 (Monte Carlo / Range Allocation)
- 每一局关卡支持指定固定的潜伏者或在区间 `[min, max]` 中暗中抽样生成实际伪人数。
- 洗牌算法分配未固定角色池，保证每一局循环均拥有截然不同的嫌疑人身份图谱。

### 2. 补给衰减与队伍规模博弈模型 (Resource Scarcity)
- 遇到食物补给点时，体力回复量严格依据**当前队内存活总人数 $N$** 呈阶梯递减：
  $$\text{Recovery}(N) = \begin{cases} 
  50 & N=1 \\
  45 & N=2 \\
  38 & N=3 \\
  35 & N=4 \\
  32 & N=5 \\
  28 & N=6 \\
  25 & N=7 \\
  22 & N=8 \\
  \max(10, 22 - (N-8)\times 2) & N>8
  \end{cases}$$
- **设计博弈点**：营救更多同伴加入可以提升夜晚存活容错并获得更多技能掩护，但同时会加剧食物消耗与伪人潜伏的潜在暗杀风险。

### 3. 步数概率检定与伪人夜袭模型
- **傍晚时刻触发概率**：依据探索面临选择步数 $S$ 动态判定：
  $$P(\text{Evening}|S) = \begin{cases} 
  0\% & S \le 2 \\
  40\% & S = 3 \\
  70\% & S = 4 \\
  100\% & S \ge 5
  \end{cases}$$
- **伪人夜袭冲动概率**：随队伍规模膨胀而上升（2人0%，3人10%，4人50%，5人70%，$\ge 6$人100%）。

## 🌐 平台适配性报告 (虎扑 AI 工坊 / 静态 Web 托管)

本项目已针对国内各大 AI 应用工坊、轻应用平台及独立 Webview 完成深度适配：

1. **绝对相对路径引用**：项目所有脚本、样式、字体、媒体资源均采用标准的相对路径（`./`），上传至任何子目录或 CDN 路径均可直接解析。
2. **Iframe 嵌套与沙箱环境兼容**：
   - 彻底解决平台由于跨域安全策略对 `file://` 或局部 `localStorage` 的拦截。当平台沙箱禁止持久化存储时，自动无感知回退至内存存储，保证游戏绝不白屏崩溃。
3. **移动端 Touch & 视口体验优化**：
   - 设置 `100dvh` 消除移动端上下边栏收缩导致的闪烁。
   - 注入 `touch-action: manipulation` 消除移动端双击延时与意外缩放。
   - 对话框右上角 NPC 立绘在小屏幕下自动缩小至合适比例，避免遮挡长文本。
4. **一键上传与托管**：
   - 将当前项目打包为 `.zip` 文件，即可直接上传至虎扑 AI 工坊、Vercel、GitHub Pages、Cloudflare Pages 等任意静态服务。

## 🎨 角色立绘与表情差分系统配置指南

本项目支持**多表情差分立绘系统**，NPC 在交谈过程中会根据每句话的感情色彩（如生气、疑惑、微笑、震惊、悲伤等）实时动态变脸：

### 1. 独立文件夹目录架构（`assets/characters/`）
各个角色拥有自己的独立子文件夹，并在其中存放各表情图片：
```
assets/characters/
├── kaze/          # 卡泽
│   ├── clam.png   # 【核心】平静（无指示时的默认照片，亦兼容 calm.png）
│   ├── happy.png  # 开心 / 微笑
│   ├── sad.png    # 悲伤 / 沮丧
│   ├── normal.png # 正常
│   ├── angry.png  # 生气 / 质问
│   ├── doubt.png  # 疑惑 / 警惕
│   └── shock.png  # 震惊 / 错愕
├── shaokexin/     # 邵可欣 (同上各表情图片)
└── mode/          # 莫德 (同上各表情图片)
```

> 💡 **优雅降级保底**：
> - 当对话文本**没有指示任何表情**时，系统严格**默认使用平静“clam”照片**。
> - 若某表情暂未放置图片，系统会自动无感知寻找 `calm`、`normal`、原图保底，最后优雅降级为带情绪徽章（💢、❓、💧、✨、❗）的高清矢量肖像，绝不出现图片裂开或报错。

### 2. 在对话中指定表情
在 [js/characters.js](file:///c:/Users/yxc18/Desktop/WebAIGame_Gnosia/js/characters.js) 中配置台词时：

- **无指示（默认使用平静 clam 照片）**：
  ```javascript
  { text: "我没什么想跟你说的，就这样。" } // 自动默认匹配 clam.png
  // 或纯字符串
  "我没什么想跟你说的，就这样。"           // 自动默认匹配 clam.png
  ```
- **显式指定表情**：
  ```javascript
  // 方式 A：对象语法
  { text: "当时，你为什么不在基地里？", expression: "angry" }
  { text: "希望我们还能一起看见太阳。", expression: "happy" }

  // 方式 B：内联标签语法
  "[生气]当时，你为什么不在基地里？"
  "[happy]希望我们还能一起看见太阳。"
  ```

修改配置后，只需双击运行 [更新配置.bat](file:///c:/Users/yxc18/Desktop/WebAIGame_Gnosia/%E6%9B%B4%E6%96%B0%E9%85%8D%E7%BD%AE.bat) 即可 1 秒同步生效！
